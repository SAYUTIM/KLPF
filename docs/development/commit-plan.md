# 日本語のコミット分割案

この資料はコミット着手前に作成した分割計画である。
以下は今回以前からの変更も含めた論理的な分割案。実際のコミットIDと公開状況はGitの履歴を参照する。
同じ`background.js`・manifest・設定メニューに複数機能があるため、ファイル丸ごとの一括追加では分けられない。
実際にコミットするときは差分を部分選択し、その段階に必要なimport先・登録先が揃っているか確認する。
特に共通解析ページの改名と呼び出し側は同じコミットへ入れる。

開発用の整理を独立したコミットにはしない。未公開のセッション再利用診断は削除済みで、GitHubへの削除コミットは不要。
通常の回帰テスト更新は対象機能へ、検査設定の強化は共通基盤へ含める。

## 1. 共通のKu-Port基盤

**`refactor: Ku-Portの通信とHTML解析を共通化`**

- フォーム直列化、ヘッダー、最小化画面、offscreen解析を共通モジュールへ整理
- attendanceParserをkuportParserへ改名し、呼び出し先も更新
- 解析ページの作成・終了競合と、所有画面の後片付けを修正
- 既存の共通関数の整理、検査設定と除外設定の更新もここへ含める

主な対象: `background/modules/kuport-*.js`、`offscreen/`、フォーム共通関数、対応するbackgroundの差分。
後の機能で参照する共通モジュールは、最初の呼び出し側と同じコミットか、それより前に追加する。

## 2. 出席率の年度取得

**`fix: 出席率を年度内の各クォーターから取得`**

- 取得可能な1Q〜4Qの条件を順に送信し、期間別データを保存
- 今年度判定と保存形式、カード表示を対応させる
- ホームへ戻ったURLでも表示する

主な対象: `features/attendanceRate.js`、`features/modules/attendance-utils.js`、出席率のbackground部分、関連登録・既存チェック。

## 3. シラバス

**`feat: 授業カードからシラバスを取得・表示`**

- 学期を選択して直接POSTで取得し、科目名・曜日・時限・教員で照合
- 今年度のカードにボタンを表示し、取得中と結果をダイアログで表示
- 30日キャッシュ、取得日時、再取得ボタンを追加
- 通信と照合を`background/kuport/`へ分離

主な対象: `features/syllabus*.js`、`background/kuport/syllabus*.js`、manifest・メニュー・backgroundのシラバス部分、関連チェック。

## 4. 掲示板

**`feat: Ku-Port掲示板の最新5件と本文を表示`**

- 全表示の一覧と本文を順番に取得し、ホームの3列目へ表示
- ブラウザ起動ごとの更新と、保存済み本文の表示に対応
- UIと取得用タブのブリッジを分離し、通常のKu-Portタブには注入しない

主な対象: `features/bulletin*.js`、`background/kuport/bulletin.js`、manifest・設定メニュー・backgroundの掲示板部分。

## 5. 競合と取消

**`fix: Ku-Port取得の待機とキャンセル処理を整理`**

- 出席率、掲示板、シラバスの待機要求を優先順位と先着順で実行
- 外部タブ作成・元タブ終了・設定OFFで取得を停止
- 取消IDの保持、画面作成中の取消、完了前の状態確認を修正

主な対象: `background/modules/priority-queue.js`、backgroundのキュー・ライフサイクル・イベント部分、既存のキューチェック。

キューを必要とする機能追加の段階から最低限の接続は必要。
このコミットを独立させる場合は、前の各コミットには機能開始に必要な接続だけを入れ、
取消の修正・整理をここへ分ける。動かない中間コミットにしないことを優先する。

## 6. ホーム表示

**`fix: ホームの表示とカレンダーの予定数を調整`**

- お知らせ、Topics、掲示板の幅と間隔を統一
- カレンダーの予定が多い日の省略表示を調整
- ホームURLと関連表示の互換性を維持

主な対象: `features/homeDashboard.js`、ホーム表示・定数・登録の関連差分。
掲示板の基本レイアウトに必須の部分は4へ入れ、ここは独立した表示調整だけにする。

## 7. 自動ログイン依存と設定同期

**`fix: 自動ログインの再送制限と機能設定を同期`**

- 認証情報未設定、自動ログインOFF、一括OFF、再送停止中は3機能の表示と取得を停止
- 認証ページの再読み込みでも保持される送信履歴と、複数タブ共通の再送上限を追加
- シラバス・掲示板のスイッチをオプションとKU-LMS内設定へ追加し、一括OFFに対応
- 重複する説明ツールチップを除去

主な対象: 共通認証モジュールとその注入定義、AutoLogin、backgroundの条件確認・停止、3機能のUI、設定用定義・画面。
共通モジュールと呼び出し側を同じコミットに含める。

## 8. READMEと日本語の説明コメント

**`docs: READMEと日本語の説明コメントを更新`**

- READMEへシラバス・掲示板、キャッシュ、認証条件、取得順序、構成、更新手順を反映
- 各ファイルの目的・実行環境・依存処理・担当範囲を記載
- 関数の入力・戻り値・待機時間・失敗時の契約を説明
- 処理上の理由を残したまま、既存の英語コメントを日本語へ統一
- CSS・HTMLと追加機能テンプレートも説明を補い、コメント方針を開発資料へ追加

主な対象: `README.md`、`docs/development/`、拡張機能・紹介サイト・GAS・テンプレートの説明コメント。
実行コードの変更とは分けて扱う。先の変更と同じファイルを含むため、該当ハンクだけを選んでステージする。コメント以外の既存変更を巻き込まない。

## 9. バージョン更新

**`chore: バージョンを4.5.0へ更新`**

- manifest、package、lockfileのプロジェクトバージョンを4.4.2から4.5.0へ更新
- 依存ライブラリのバージョンは変更しない

## メッセージの書き方

件名は上記の短い日本語、本文は2〜4行で「変えたこと」「理由」「確認した範囲」を書く。
実機未確認・未実行のチェックを「確認済み」と書かない。
リファクタリング時の静的チェックは構文・JavaScript・HTMLが成功。CSS検査は出力なしで終了コード1となり、成功を確認できていない。自動テスト・実ブラウザは未実行なので、リリース前の確認が必要。
バージョン更新は上記9へ分ける。コミットとpushの対象であり、リリース作成は含めない。

## 実行時の方針

- 計画の承認後に、上記の順で署名付きコミットを作成する。
- ファイル単位では分けられない変更は差分を部分選択し、必要な共通モジュール・manifest登録・設定キーを揃える。
- コミット後に署名と差分を確認し、承認された範囲でpushする。リリース・タグ・配布ZIPは作成しない。
- 削除済みの未公開診断コードを履歴へ追加しない。
